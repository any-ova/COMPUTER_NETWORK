# RS-232 Chat (2 ПК) — Канальный уровень по методичке + защита данных циклическим [7,4]

## 1. Что реализовано
Проект реализует взаимодействие до прикладного уровня для сети из **2 ПК**, соединённых по **RS232C (нульмодем)** или через эмуляцию портов (com0com).

Слои:
- **Физический уровень** (`SerialPhysicalLayer`, `SerialConfig`): открытие COM‑порта и обмен байтами.
- **Канальный уровень** (`Frame`, `FrameIO`, `DataLinkLayer`): передача кадров по структуре методички:
    - старт/стоп `0xFF`
    - адреса dst/src (в т.ч. broadcast `0x7F`)
    - типы кадров: **I, Link, Uplink, ACK, Ret**
    - для I и Link — поля `len` и `data` присутствуют
    - для ACK/Ret/Uplink — `len` и `data` отсутствуют
    - **поле data защищено циклическим [7,4]-кодом** (по вашему требованию “защитить передаваемую информацию” для данных)
    - реализован **byte stuffing** для данных (чтобы `0xFF` не ломал кадр)
- **Прикладной уровень (демо)**: консольный чат (`DemoChatApp`):
    - broadcast сообщения
    - личные сообщения по адресу (`/to <addr>`)
    - история сообщений (`/history show|clear|save`)
    - системные сообщения `SYSTEM>`
    - команды `/link`, `/disconnect`

> Передача файла по заданию — следующий этап (будет строиться поверх I‑кадров, не добавляя новых типов кадра, чтобы не отходить от методички).

---

## 2. Термины
- `FLAG` = `0xFF` — стартовый/стоповый байт кадра.
- `BROADCAST` = `0x7F` — широковещательный адрес получателя.
- `dst` — адрес получателя (1..126 или 0x7F).
- `src` — адрес отправителя (1..126).
- `type` — тип кадра.
- `len` — длина данных **до кодирования** (0..255).
- `data` — полезные данные (только для I и Link).

---

## 3. Структура кадра (строго по методичке)
Формат:

| Поле | Размер | Примечание |
|------|--------|------------|
| Start | 1 байт | 0xFF |
| dst | 1 байт | адрес получателя |
| src | 1 байт | адрес отправителя |
| type | 1 байт | тип кадра |
| len* | 1 байт | только для I и Link |
| data* | переменно | только для I и Link |
| Stop | 1 байт | 0xFF |

\* Для **ACK**, **Ret**, **Uplink** поля `len` и `data` отсутствуют.

---

## 4. Типы кадров
- **I** — информационный кадр. Передаёт короткое сообщение (текст).
- **Link** — установка соединения/объявление пользователей (dst=broadcast). Data содержит список `addr=nick`.
- **Uplink** — разрыв соединения (dst=broadcast), без данных.
- **ACK** — подтверждение приёма I‑кадра (только для unicast), без данных.
- **Ret** — запрос повторить “последний отправленный кадр” (unicast), без данных.

---

## 5. Защита данных циклическим [7,4]
Для кадров I и Link поле `data` перед передачей:
1) кодируется циклическим двоичным **(7,4)** кодом (n=7, k=4),
2) упаковывается в поток байт,
3) дополнительно проходит byte stuffing (экранирование 0xFF/0xFE).

На приёме выполняется обратная операция:
- unstuff → декодирование (исправление одиночных ошибок по синдрому) → получение исходных байтов data.

**Почему нужен stuffing:** так как границы кадра определяются байтом `0xFF`, этот байт нельзя “случайно встретить” внутри данных; stuffing это предотвращает.

---

## 6. Параметры COM‑порта
Используются значения по умолчанию (пример):
- 9600 baud
- 8 data bits
- 1 stop bit
- parity NONE
- flow control NONE

При открытии печатается лог:
`[PHY] Opened COMx: baud=9600 dataBits=8 stopBits=1 parity=NONE flow=NONE`

---

## 7. Как запустить (1 ПК, com0com)
### 7.1 Подготовка
1) Создать виртуальную пару портов `COM1 ↔ COM2` в com0com.

### 7.2 Запуск
Запустить **2 экземпляра** `DemoChatApp`:

**Окно A**
- COM: COM1
- addr: 1
- nick: Alice

**Окно B**
- COM: COM2
- addr: 2
- nick: Bob

После запуска рекомендуется выполнить `/link` в обоих окнах.

---

## 8. Команды DemoChatApp
- `/link` — отправить Link (broadcast).
- `/users` — показать текущий список известных пользователей.
- `/all <text>` — broadcast сообщение.
- `/to <addr> <text>` — личное сообщение на адрес.
- `/history show` — показать историю.
- `/history clear` — очистить историю.
- `/history save <filePath>` — сохранить историю в файл.
- `/disconnect` — отправить Uplink (broadcast).
- `/exit` — выход.

Сообщение также **дублируется в своём окне**, как в методичке.

## 9. Тесты работоспособности (кратко)
См. файл `TESTS.md`. Минимально:
1) `/link` в обоих окнах → обновление users.
2) `привет` в A → появляется в B.
3) `/to 2 личное` в A → появляется в B (unicast).
4) `/disconnect` в A → B сообщает о разрыве.

## 10. Зачем нужен AppCodec (если будем расширять прикладной уровень)
В методичке прикладной “пакет сообщения” состоит из 3 полей:
- получатель (имя),
- отправитель (имя),
- текст.

`AppCodec` — это кодер/декодер, который упаковывает эти 3 поля в последовательность байтов для поля `data` I‑кадра и распаковывает обратно. Это удобно для:
- личных сообщений “по нику”,
- истории и отдельных окон диалогов,
- расширений (например, передача файла как прикладные пакеты).

Сейчас проект работает и без AppCodec (мы отправляем только текст), но для “полноценного прикладного уровня как в методичке” он пригодится.
